# Dashboard security floor

Distilled 2026-07-23 from the deep-research report at [`research/Patchyard-SSR-Admin-Content-Safety-and-Upload-Hardening.md`](../research/Patchyard-SSR-Admin-Content-Safety-and-Upload-Hardening.md) (OWASP contextual-encoding + CSP3, pulldown-cmark/ammonia, the Google inactive-content header recipe, `image`-crate advisories, PortSwigger CSP-bypass research). Binding rules only; each activates at the session that first makes it real, and every mechanizable rule moves into a check. Build-session prompts cite this file.

**The reframe that governs everything below.** At three named admins on one internal tool, the dominant failure mode is not mass abuse - it is **one crafted request (text or screenshot) that executes in the kill-switch session.** The admin who views a request is the admin who can halt the factory, so a stored-XSS or content-injection in that browser is control-plane compromise, not defacement. And the #1 mistake teams make: treating "we re-encode images and have a strict CSP" as permission to be sloppy about *where untrusted strings enter templates.* **Contextual output encoding is the primary defense; CSP and headers are defense-in-depth, never the plan.** Every Askama `|safe` and every markdown-HTML emission path is a security boundary review gate, equal in severity to a raw SQL concat.

## A. Rendering / CSP - activates at session 11 (dashboard part 1)

- **Contextual HTML escaping by default.** Askama `.html` templates, never a global `escape = "none"` and never `|safe` on untrusted data. Untrusted text is banned from URL / JS / CSS / event-handler sinks; any URL built from untrusted input is scheme-allowlisted (`http`/`https`/`mailto` only - never `javascript:`/`data:`).
- **Markdown (pulldown-cmark) - filter events, do not look for a disable flag.** There is **no `DISABLE_RAW_HTML` option**; CommonMark emits raw HTML by default. Drop `Event::Html` and `Event::InlineHtml` (and HTML blocks) from the event stream before `html::push_html`, and optionally run [ammonia](https://github.com/rust-ammonia/ammonia) with a minimal allowlist after. Beyond raw HTML: allowlist link schemes on `Tag::Link`, **do not** enable `ENABLE_HEADING_ATTRIBUTES` for untrusted input (it injects `{#id onmouseover=…}`), and strip/scope images (`/decisions` and `/codebase` render governance files; request text is stricter - plain structure only). Governance markdown (decision log, codebase metrics) is *semi-trusted*: still no raw HTML, but from a pinned reviewed repo.
- **Strict CSP on all HTML responses**: `default-src 'none'`; `script-src` **nonce-only** (a per-response nonce for the one inline `EventSource` fragment - **no `'unsafe-inline'`, and no `'self'`** while uploads are same-origin, because a same-origin upload is a polyglot-script risk); `style-src 'self'`; `connect-src 'self'` (the SSE endpoint); `base-uri 'none'`; `object-src 'none'`; `form-action 'self'` (omitting it enables scriptless form-hijacking exfil); `frame-ancestors 'none'`. Add a CSP violation-report endpoint and a synthetic header check in deploy.
- **Auth hardening (the A-11 requirement, since this session's viewer holds the kill switch)**: session cookie `HttpOnly` + `Secure` + `SameSite=Strict`; **CSRF token on every state-changing route** - submit, pause/resume, kill, full-stop (and upload, session 12); login throttling; session-id rotation on login (fixation defense); idle **and** absolute expiry; account disable/reset; audit events for logins, submissions, and control actions.

## B. Upload pipeline - activates at session 12 (upload hardening + threat model)

- **Gate before trusting the body**: authn/authz, size limit, per-request and per-user quotas, rate limit, and a **CSRF token on the upload route** (missing from the original SPEC contract - add it).
- **Validate → limit → time → re-encode → store clean only**: magic-byte allowlist (PNG/JPEG; reject archives/executables/**SVG** - SVG is active content); **strict width/height/allocation limits set explicitly before decode** (never the crate default "no limit" - decoder/decompression bombs); a **wall-clock timeout around decode on a blocking thread pool** (missing from the SPEC contract - add it); re-encode to clean PNG/JPEG (re-encode is the real neutralizer, and it covers EXIF stripping - do **not** hand-copy APP1 metadata); store and serve **only the re-encoded bytes** under server-generated IDs; fail closed. Original uploaded bytes are never web-reachable (if retained at all, an offline quarantine dir).
- **Filesystem**: canonical server-generated names/IDs, user filename (RFC 7578) ignored entirely and the serve path never derives from user input; `create_new` + fsync + same-filesystem atomic rename; `O_NOFOLLOW`/trusted-base-fd against symlink/hardlink/TOCTOU; least-privilege dir; disk-full fails closed (alert + HTTP 507).
- **Serve uploads with the full inactive-content header set** (Google recipe): `X-Content-Type-Options: nosniff`, correct image type or `application/octet-stream`, `Content-Disposition: attachment`, `Content-Security-Policy: sandbox; default-src 'none'`, `Cross-Origin-Resource-Policy: same-site`. A separate content origin is *optional at this scale* if these headers are applied rigorously - not worth the multi-service ops cost for internal ERP screenshots.
- **Supply chain + fuzz**: minimize `image` crate features (png/jpeg only - the HDR decoder's CVE history is why), `cargo audit` in CI; a **time-boxed `cargo-fuzz` campaign** against the ingest/decode and path-handling targets with a declared seed corpus and budget, corpus retained for regression. "Zero unresolved findings within budget" means the declared targets ran to the declared budget with every finding triaged - not "we ran fuzzing."

## Deliberately not adopted at this scale

Third-party antivirus/CDR scanners for PNG/JPEG after re-encode (marginal for internal ERP screenshots); a mandatory separate content origin (headers-first suffices); continuous 24/7 fuzz fleets (time-boxed per-session is the calibrated form). **At 100× / public app**: separate content origin becomes worth it, a second factor on the kill action, and continuous fuzzing.
