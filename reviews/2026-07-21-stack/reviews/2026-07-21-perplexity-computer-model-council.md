
# Patchyard Factory stack review — model council synthesis

*Council: Claude Fable 5, GPT 5.5, Gemini 3.1 Pro. Three independent reviews of the 2026-07-21 stack packet, synthesized around where the models converge, diverge, and see uniquely.*

## Bottom line

All three council members converge on the same top verdict: the **self-hosted GitHub Actions runner on the control-plane VM** is both the most attackable trust boundary and the highest-leverage thing to replace outright — and all three name the same replacement, the "one-line `runs-on` fallback" already in your packet. That unanimity across three families reviewing the same document is the strongest signal in this synthesis.

All three also agree that **Firecracker is over-engineered for this scale** (default to rootless Podman) and that **LISTEN/NOTIFY has a real durability gap** (a missed-listener window strands a request at 1×, not at 10×). They disagree meaningfully on the observability posture, on the second-most-dangerous boundary, and on how to characterize what cross-family review actually fails at. The unique findings are all worth acting on.

## Where models disagree

| Topic | Claude Opus 4.8 (Fable 5) | GPT 5.5 | Gemini 3.1 Pro | Why they differ |
|---|---|---|---|---|
| Fate of OTLP/Tempo and the `grafana_ro` TCP role | Delete both from phase 1; `grafana_ro` is a standing inbound listener, *not* "expose-never-require" — it trades A56's cleanest security property for a dashboard convenience answerable in `psql` | Keep trace-shaped `tracing` instrumentation and store run/trace IDs in the ledger now; make OTLP export a disabled-by-default switch until the first "cannot explain from SQL + transcripts" incident | Fail-open OTLP is architecturally correct; the real gap is that `traceparent` won't propagate across `LISTEN/NOTIFY` unless you inject W3C trace IDs into the payload | **Different weighting of the security cost vs the future debuggability value.** Fable emphasizes the concrete boundary regression today (`grafana_ro` opens the one TCP hole); GPT emphasizes optionality (instrument now, ship the backend later); Gemini takes the packet's choice as given and focuses on a hidden correctness bug in the trace path itself ([Kunwar on OTel across async boundaries](https://www.kunwar.page/chapter/095-distributed-tracing-opentelemetry-jaeger-tempo), [Tempo distributor limits](https://grafana.com/docs/tempo/latest/reference-tempo-architecture/components/distributor/)) |
| Second-highest-priority trust boundary after the CI runner | Preview/evidence stage: the headless helper holds a live dev-fleet bearer token, has network access to the leased host, and processes patches derived from untrusted content — the lethal trifecta reassembles here in miniature | Publisher / GitHub App boundary: GitHub App installation tokens *inherit all granted permissions and repositories unless narrowed at token generation*; the publisher is the point where a low-privilege patch becomes privileged execution ([GitHub App installation auth docs](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation)) | Patch application on the control-plane VM: a maliciously crafted diff with directory traversal or symlink overwrite techniques applied via `git apply` could write outside the worktree and reach the ledger or the GitHub App key | **Different mental models of where untrusted content re-enters privilege.** Fable follows the credential (bearer token in the browser stage); GPT follows the identity (App token scope at mint time); Gemini follows the write (bytes hitting `git apply` on the crown-jewel host). All three are real and non-overlapping — treat as three findings, not one |
| The A86 improvement proposer | The single strongest point of the design: R19 + A1 + A86 (human-reviewed diffs, no in-place revision, one open PR at n≥10 with cited run IDs) is *exactly* the write-ahead-validation defense the memory-poisoning literature recommends ([AgentPoison arXiv 2407.12784](https://arxiv.org/abs/2407.12784), [MINJA-style study arXiv 2606.04329](https://arxiv.org/html/2606.04329v1)) | Delete the proposer daemon from phase 1; keep the R19 learning loop; replace with `factoryctl lessons report --since ...` emitting a Markdown draft and never invoking a model. Both are internally consistent — Fable is right about the safety envelope, GPT is right that a script achieves the same phase-1 outcome without a scheduled agent seat |
| What "the AI layer is blind to" is really about | *Error correlation across frontier families rises with capability*; a "diverse" panel of 9 models across 7 families delivers only ~2 votes' worth of independence — the dangerous failures are the silent-agreement ones the reviewer is structurally blind to ([Great Models Think Alike](https://arxiv.org/abs/2502.04313), [Correlated Errors in LLMs](https://arxiv.org/html/2506.07962v1), [Correlated Errors Undermine LLM Evaluation Panels](https://arxiv.org/html/2605.29800v1), [Self-Consistent Errors ACL 2025](https://aclanthology.org/2025.emnlp-main.238/)) | *Review infection via shared context*: all reviewers still read attacker-influenced text (request body, comments, transcript, rationale) unless untrusted observations are separated from trusted obligations via an information-flow / noninterference property ([OWASP LLM01:2025](https://genai.owasp.org/llmrisk/llm01-prompt-injection/), [Prompt Infection paper arXiv 2410.07283](https://arxiv.org/abs/2410.07283), [RTBAS arXiv 2502.08966](https://arxiv.org/abs/2502.08966), [AgentDojo arXiv 2506.01055](https://arxiv.org/abs/2506.01055)) | *Hallucinated refutations by the critic*: cross-family critics fabricate confident counterexamples (fake CVEs, non-existent code paths) that the A77 debate protocol has no empirical check to invalidate, so correct PRs get rejected ([adversarial-stack paper arXiv 2604.19049](https://arxiv.org/html/2604.19049v1), [Hexisteme on challenge-triggered reverification](https://hexisteme.github.io/notes/challenge-triggered-reverification.html)) | **Different failure directions.** Fable's is *false negatives on wrong-but-plausible builds* (silent agreement approves bad code). ## Unique discoveries

| Model | Unique finding | Why it matters |
|---|---|---|
| Claude Opus 4.8 (Fable 5) | **Model deprecation churn (~60-day Anthropic notice, ~6-month OpenAI GA / much shorter for chat/Codex snapshots) rots the replay guarantee.** Every ~2–3 months a seated model deprecates → bench re-qualification + a `policy/` routing PR + human merge. Replay fixtures pinned to snapshots become unreproducible the day the seat retires — the acceptance suite fails not because the factory regressed but because the model is gone ([Anthropic deprecations](https://docs.anthropic.com/en/docs/about-claude/model-deprecations), [OpenAI deprecations](https://developers.openai.com/api/docs/deprecations)) | Invisible in the 17-session phase-1 plan and expensive in year two. Decide *now* whether replay fixtures pin to snapshots (reproducible but expiring) or to aliases (durable but non-deterministic); budget a standing bench-refresh cadence |
| Claude Opus 4.8 (Fable 5) | **Reviewer/seat yield base rates as day-one instrumentation.** Log per-reviewer-seat "raised N findings, M conceded on run class Y." A finding-rate collapse after a model swap is either clean builds or affinity agreement — indistinguishable without the base-rate series | This is both the Q4 mitigation and the Q5 "instrument from day one" answer; a few extra ledger columns, not a new system, and the counterfactual is unrecoverable once the seat retires |
| Claude Opus 4.8 (Fable 5) | **The `grafana_ro` role is *not* expose-never-require.** A56 self-describes it as "the sole TCP exception" — a standing inbound listener bound to the VPC. The A82/A84 justification ("expose-never-require keeps A68 intact") does not survive contact with A56's own text | The design's stated security invariant contradicts a stack choice made in the same doc; either the invariant needs weakening or the choice needs to go |
| GPT 5.5 | **Idempotence as an under-instrumented formal property.** Require a transition table proving every stage is idempotent, fenced, or terminal under retry, covering: patch verified but publisher crash before branch push; branch pushed but PR creation timeout; PR exists but ledger commit failed; kill arrives while publisher holds a lease; control-plane restore replays an already-published run | Every conditional state change should be `UPDATE ... WHERE state = old_state AND lease_token = token`; every handoff fenced by a monotonic attempt number. The acceptance criteria touch these cases but the property to prove — not just test — is missing |
| GPT 5.5 | **GitHub App installation tokens inherit *all* granted permissions and repositories unless narrowed at token generation.** The publisher must specify `permissions` and repository narrowing on every `POST /app/installations/{id}/access_tokens` call ([GitHub App installation auth docs](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation)) | The packet says the App key is minted per-run, but doesn't require per-mint scope narrowing. Default-broad tokens undo the "short-lived spend-capped" spirit of A61 |
| GPT 5.5 | **Make `.github/workflows/`, `infra/`, verifier code, routing policy, and evidence-serving code either denied paths for autonomous lane-A runs or require a human plan-bin path.** The `caps` and `deny-paths` verifier subcommands already exist — extend the deny-list to any file whose modification would rewrite the factory's own gates | Turns "the factory can't merge itself" into a syntactic property enforced by the deterministic verifier, not just by human vigilance |
| Gemini 3.1 Pro | **OpenTelemetry trace context is lost at the `LISTEN/NOTIFY` boundary.** Auto-instrumentation breaks across async/message-queue boundaries; the `traceparent` header will not survive Postgres NOTIFY unless the payload explicitly carries a W3C trace ID that the daemon extracts on wake ([Kunwar on OTel + Tempo across async](https://www.kunwar.page/chapter/095-distributed-tracing-opentelemetry-jaeger-tempo)) | Without this, the dashboard's intake trace and the supervisor's pipeline trace are *permanently orphaned*, defeating the whole point of the OTLP/Tempo investment. If you keep OTLP in phase 1, this is the one line of glue that determines whether it works |
| Gemini 3.1 Pro | **Hallucinated refutations as a distinct AI failure mode** — the critic confidently fabricates a fake vulnerability, CVE number, or non-existent code path; the A77 debate resolves by escalation, not by an empirical test of the *critic's* claim | The A77 escape hatch ("empirically checkable findings resolve by running the check, never by vote") is the right primitive, but it fires on the *author's* claims. Extend it to reviewer findings: a critic that names a code path must produce a passing/failing check against it before the finding is admissible |

## Comprehensive analysis

**High-confidence findings — where the council converged.** The unanimous top verdict is that the self-hosted GHA runner on the control-plane VM has to move. Three models, three families, three different threat framings arrive at the same target and the same replacement — the one-line `runs-on: ubuntu-latest` fallback A76 already documents. That is the most reliable signal a council produces: when Claude Opus 4.8 (via Fable 5), GPT 5.5, and Gemini 3.1 Pro converge from different angles (Fable via internal-consistency auditing, GPT via information-flow reasoning, Gemini via supply-chain risk), the finding is almost certainly right for reasons that don't depend on any single reviewer's frame. Treat this as a session-0 change, not a phase-2 nicety. The Firecracker-vs-Podman consensus is nearly as strong: A57/A59/A61 already emptied the worker's blast radius, so the microVM's guest-kernel isolation is protecting nothing worth reaching and adds a kernel supply chain you don't need to maintain. Podman with the Docker root socket unreachable is the honest match at ~20 runs/week; revisit if the worker ever holds persistent data. The LISTEN/NOTIFY durability gap is the third convergent finding, and the fix is small: treat NOTIFY as a latency optimization, run a startup + timer sweep with `SELECT ... FOR UPDATE SKIP LOCKED` on `requests`, and add "crash during the NOTIFY window" to the acceptance fixtures alongside the existing crash-before/after-branch-push cases. This preserves the "cloud queues excluded — Postgres does it" ruling while engaging its actual stated reason.

**Areas of divergence — how to weigh them.** Observability is where the council splits most cleanly, and each model's position matches the invariant it was protecting. Fable 5 protects **A56's socket-only Postgres boundary** and correctly notes that A84's `grafana_ro` role reads as "expose-never-require" but *is* a standing VPC-bound listener — an actual TCP exposure. GPT 5.5 protects **future debuggability under stress** and separates instrumentation (write trace IDs into the ledger now, cheap) from ingestion (defer Tempo until you have a real incident SQL can't answer). Gemini 3.1 Pro protects **the trace's own correctness** and points out that even if you ship Tempo tomorrow, the traces won't join across `LISTEN/NOTIFY` without a payload-carried W3C trace ID — a bug you cannot detect from the design doc alone. The synthesis: take all three. Delete the `grafana_ro` TCP exception in phase 1 (Fable); keep `tracing` instrumentation and store trace IDs in the ledger (GPT); and if Tempo returns later, inject `traceparent` into the NOTIFY payload (Gemini). None of these findings contradict the others; they compose. The three's disagreement about the "second-highest boundary" (preview stage / publisher token scope / patch application) similarly composes into a checklist — three real boundaries, three different mitigations, none of them mutually exclusive.

The cross-family review debate is more interesting because the models are describing three different failures of the same mechanism. Fable's error-correlation frame (silent agreement → false negatives on wrong-but-plausible builds) is the paper-cited long-term structural risk and points to reviewer-yield instrumentation and stronger reliance on the deterministic verifier. GPT's review-infection frame (shared adversarial context → propagation across agents) is the acute prompt-injection risk and points to giving the reviewer a *different view* of the run — normalized diff, verifier outputs, tree hashes, minimal task statement — before the author's transcript is admissible. Gemini's hallucinated-refutation frame (critic fabricates → false positives on correct builds) is a workflow-availability risk and points to extending A77's "empirically checkable" primitive to the critic's own claims. These are three different attacks, not competing theories. The design engages none of them explicitly today, and the strongest of the three depends on your operational tempo: if you fear silently merging bad patches, weight Fable's; if you fear the factory rejecting valid work under attack, weight Gemini's; if you fear the whole review being contaminated by one poisoned input, weight GPT's. In practice, adopt all three primitives (yield-base-rate ledger columns, separate reviewer view, empirical check for critic claims) — none is expensive individually.

The A86 improvement proposer is the one place the council genuinely disagrees on direction. Fable calls it the design's strongest point (a textbook write-ahead-validation defense against the memory-poisoning literature) and would keep it. GPT calls it the clearest "prove the factory works first" item and would replace it with `factoryctl lessons report` in phase 1. Both are internally consistent, and both are correct about different things: Fable is right that R19 + A1 + A86 is a genuinely well-designed defense against AgentPoison/MINJA-style attacks, and GPT is right that a scheduled agent seat is unnecessary machinery when a Markdown-emitting script preserves the same n≥10 threshold and the same auditability. The synthesis-neutral read: keep A86's *contract* (schema, threshold, human-merge PR, cited run IDs, one open PR) and defer only the *agent invocation* to phase 2; that keeps the memory-poisoning defense intact while removing a scheduled seat from phase 1.

**Unique insights worth noting.** Three of the unique findings are strong enough to be acted on independently of the convergent verdicts. Fable's **model deprecation churn** point is the most economically consequential: your replay-fixture provenance guarantees expire on the same clock as your seats, and the packet does not budget for it. Decide the pinning question — snapshot (reproducible, expiring) vs alias (durable, non-deterministic) — before session 0, because the acceptance suite is designed around replays. GPT's **idempotence transition table** turns your acceptance-criterion tests into a property you can prove; extending the `deny-paths` verifier to `.github/workflows/`, `infra/`, verifier code, and routing policy makes "the factory can't rewrite its own gates" a syntactic invariant rather than a review-time vigilance. GPT's **per-mint GitHub App token narrowing** is a two-line fix that closes a real default-broad-token gap: mint tokens with `permissions` and repository scope on every call, not just short-lived expiry. Gemini's **`traceparent` propagation across LISTEN/NOTIFY** is the finding you're most likely to miss until the first Tempo incident; add a `trace_id` column to the `NOTIFY` payload if OTLP survives phase 1.

**Recommendation.** Sequence the changes by convergence strength and cost. In session 0, adopt the three unanimous items (GHA runner off the control-plane VM via `runs-on: ubuntu-latest` or a disposable runner droplet; default to rootless Podman and stop probing Firecracker; add the LISTEN/NOTIFY startup + timer catch-up sweep to the supervisor with an acceptance fixture). In the state-layer session, delete the `grafana_ro` TCP exception and keep Prometheus `/metrics` + `tracing` writing IDs into the ledger; defer Tempo. In the AI-layer session, add reviewer-yield base rates as ledger columns, give the reviewer a separate view of the run (normalized diff + verifier outputs + minimal task statement, no author transcript until after first finding), and extend A77's empirical-check primitive to critic claims. In the identity session, narrow GitHub App tokens at mint time. In the verifier session, extend `deny-paths` to workflow/infra/verifier/policy directories. Decide the replay-fixture pinning policy (snapshot vs alias) as a session-0 documented decision. Keep A86's contract, defer its agent invocation. That sequence retires the sharpest attack surface, closes the two boundary regressions the design contradicts itself on, and turns three of the AI layer's most-cited failure modes into invariants you measure instead of hope for — without violating any of the packet's invariants.
